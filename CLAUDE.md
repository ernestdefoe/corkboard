# Corkboard: working rules

- **Commit straight to `main` and push. Never open a pull request on this repo.** Commit subjects are conventional (`feat:`, `fix:`); the release drafter bumps from the subject.
- `js/dist` is committed and is what forums load. After any change under `js/src`, run `npm run build` in `js/` (from a fresh `npm ci`) and commit the bundle; CI fails if it is stale.
- Publishing a release is Ernest's click. Nothing is announced until he says so. Every change goes to the Command Center for review first. New extension: dev + ernestdefoe.dev only until Ernest has tested it.
- Scope and Ernest's decisions: `~/github/command-center/scopes/boards.md` (name Corkboard, all recommendations taken, 2026-11-13). Mockup: https://claude.ai/artifact/RXMrdRXp86WxSkQj7rSGut

## Design rules that exist for a reason

- **One read rule.** `Scope\BoardVisibility` (public / members / team / private; private boards ignore group rows) and `Scope\CardVisibility` (a card follows its board). The API, widgets, notifications (checked again at send time), the outbox, the discussion chip and the calendar feed all use it. Roles are `Access` (viewer < commenter < editor < manager; owner and moderators are managers; completed/archived boards are read-only except reopen). Its memo is an instance WeakMap keyed by the actor; `CorkboardServiceProvider` makes Access a singleton so every class shares it. A list primes roles for its whole page (`Access::prime`), never one board per row.
- **🚨 `Card::board()` ignores the soft-delete scope** (so `$card->board` is never null); controllers check `deleted_at`. `Board` has a global scope hiding deleted boards.
- **The API** is JSON:API resources (`src/Api/*Resource.php`, base `Api\Resource` with `view`, `writeOnly`, `list`); every write goes through the services. Lists are Index filters: the card lists (my cards, due soon, a big column's next cards, archived) on `corkboard-cards` (`Api\CardList`), the tabs and template boards on `corkboard-boards` (`Api\BoardList`); built-in templates are the `corkboardTemplates` forum attribute. History is the read-only `corkboard-activity` resource (`Api\ActivityResource`, names in `meta.names`); people are found through core's own `GET /api/users?filter[q]=` (needs `searchUsers`) and groups from the forum's `app.store` (never Guests or hidden groups). `src/Api/Handler` holds only actions (clone, pin, moving, start a discussion, feed tokens), the version poll, the progress widget and the calendar feed.
- **Write guards**: every Update/Delete endpoint has `->can('update'|'delete')` and every create on a board or card `Resource::createOn()` (parent visible, then `assertCan`), answered by the model policies in `src/Policy` (registered in extend.php), which read `Access`. The services check again with the field-level refusals; keep both in step.
- **🔒 Linked discussion** (`Presenter::discussion`): read through core's posts endpoint with `Flarum\Api\Client` as the viewer (with their session), never from the models, so other extensions' API middleware and field changes (Spoiler Shield's `RedactApi`, hidden posts, private discussions) apply. `JsonApi::process()` would skip middleware: don't switch to it. A refusal is `throw Refusal::because('key', 'field')`: `Http\TranslateRefusals` answers it 422 with the translated sentence on that field.
- **Throttle**: creating cards, comments, boards and team rows, cloning and starting a discussion are refused (429) once a member has 30 history rows of those kinds (`Throttle::COUNTED`) from the last minute; drags and edits don't count. Moderators aren't limited. The "moving" hint is dropped silently (still 204) past 5 per 10 s per member (`Handler\Moving`, cache counter). GDPR: anonymize keeps a member's comments, delete removes them (as flarum/gdpr does posts).
- **The board payload is slim and constant in queries** (`Presenter::board`: 10 queries for 1 or 300 cards, tested on SQLite, MySQL `dev_` and PostgreSQL). Descriptions, checklists and comments load only when a card opens. Boards over 500 open cards send each column's first 150.
- **Positions** are integers with gaps of 1024, renumbered in one CASE update when a gap closes (`Positions`). No row locks: two drops into one slot share a position and lists order by position, then id; the next drop there renumbers.
- **Notifications**: `NotificationSyncer::sync()` hides matching alerts for everyone not in the new list, so every blueprint's data carries the activity id. 🚨 Core registers a type's email switch only for a mailable blueprint; ours aren't (email goes through `Mail\Outbox`, one email per person after updates stop for 2 minutes, at most 10), so extend.php registers the `notify_<type>_email` preferences itself. The digest's own switch stops all Corkboard email.
- **Realtime** pushes ids and a version only, to each team member's `private-user=<id>` channel (up to `Push::MAX_FANOUT`, 50 people; flarum/framework#5220 would allow a board channel). Everyone else polls `/boards/{id}/version` every 20 s while visible. On only when flarum/realtime is enabled (`Integration('flarum-realtime')` in `Extend\Conditional`) and its Pusher is bound (`Push::available`).
- **Drag**: `components/drag.ts` (pointer events, touch hold 180 ms, non-passive touchmove once lifted, edge auto-scroll). 🚨 scroll-snap is switched off while dragging (`.CorkboardDragging`) or the strip never scrolls on. Keyboard: Space/arrows/Space/Escape with an `aria-live` region; no `onkeydown` returns false.
- **Modal attrs**: never name one `state` (core passes its own modal manager as `state`); ours is `board`.
- **The discussion chip** (`Api\DiscussionCards`, deferred field, one query) only once `ernestdefoe-corkboard.linked` is set and only on the discussions endpoints.
- Migrations: one table per file (`Migration::createTableIfNotExists`, `2026_11_12_2300NN_*`, in foreign-key order); forums from before the split skip them, and `2026_11_19_000005_upgrade_from_corkboard_1_0` moves 1.0.0's `users.corkboard_feed_token` into `corkboard_feed_tokens` and forgets the rows of 1.0.0 migration files that are gone (a rollback would stop at them). Team rows are unique per (board, user) and (board, group) (`000006`): `Team::add` upserts.
- extend.php uses string literals for setting keys. Lazy chunk: one entry (`components/index.ts`), namespaced chunk ids and its own chunk-loading global.
- Renown's side lives in Renown (`Integration\Corkboard`): it listens to `CardCompleted` / `CardReopened` / `CardDeleted` and reads `corkboard_boards`, `corkboard_members`, `corkboard_assignees`. Keep those columns' meaning stable.

## Testing

- `composer test:setup` (SQLite: `touch /tmp/ck_test.sqlite`, `DB_DRIVER=sqlite DB_DATABASE=/tmp/ck_test.sqlite`) `&& composer test`, then `~/github/scopes/corkboard/dbtests.sh` (MySQL `dev_` + PostgreSQL in Docker; prints the driver). `composer analyse:phpstan`.
- `cd js && npm ci && npm run build && npm run format-check`.
- Local forum `~/Herd/corkdev` (https://corkdev.test, MySQL `corkdev`, prefix `ck_`). Seed: `php ~/github/scopes/corkboard/seed.php` (runs the showcase seed `~/github/showcase/seeds/99-corkboard.php`). Browser checks: `interact.mjs` (keyboard, mouse, touch, typing), `shots.mjs`, `themes.mjs` (THEME=colored|bespoke), `widgets.mjs`, `project.mjs`. Devices: `proxy.mjs` (localhost:8789, signed in by a `claude-shots` remember token) for the iOS Simulator and Android emulator.
